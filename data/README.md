### ⚠️ 1 — กด MARK แค่ 3 เหตุการณ์ · ช่วง test ไม่มีเลย

| # | ชุด | ชนิด | เริ่ม (เวลาบอร์ด) | pm2_5 ฐาน → สูงสุด |

วัดได้แค่ false alarm — ต้องเขียนเป็นข้อจำกัดในรายงาน

## รูปแบบไฟล์ raw

ชื่อไฟล์ `AG_YYYYMMDD_HHMMSS.csv` — ขึ้นไฟล์ใหม่ทุกวันหรือทุกครั้งที่บูต

```csv
timestamp_iso,pm1_0,pm2_5,pm10,temp_c,humidity_pct,tvoc_ppb,eco2_ppm,co_ppm,label
2026-09-23T14:30:00+07:00,8,12,15,28.4,62.1,145,520,0.4,normal
2026-09-23T14:30:01+07:00,9,13,16,28.4,62.0,148,524,0.4,normal
2026-09-23T14:32:10+07:00,45,118,142,28.9,61.2,890,1240,0.6,marked
```

**ค่าที่หายไป → เว้นว่าง** ไม่ใช่ `0` หรือ `-1`
เพราะ `0` เป็นค่าที่เป็นไปได้จริง แยกไม่ออกจาก "อ่านไม่ได้"

## รูปแบบไฟล์ events

```csv
start_iso,end_iso,label,note
2026-09-23T14:32:05+07:00,2026-09-23T14:41:00+07:00,incense,จุดธูป 1 ดอก ห่าง 2 m ปิดหน้าต่าง
```

🔑 **จดบริบทใน `note` ให้ละเอียด** — ระยะห่าง หน้าต่างเปิด/ปิด พัดลมทำงานไหม
ตอนวิเคราะห์ว่าทำไมบาง event จับไม่ได้ ข้อมูลตรงนี้คือคำตอบ

## โปรโตคอลเก็บข้อมูล

1. วางเครื่อง**ที่เดิมทุกครั้ง** สูงจากพื้น 1.0–1.5 m ห่างหน้าต่าง/ประตู/แอร์
2. เก็บช่วงปกติให้ได้**อย่างน้อย 3 วันต่อเนื่อง**ก่อนเริ่มสร้าง anomaly
   *(ต้องมีข้อมูลปกติเยอะพอให้โมเดลเรียนก่อน)*
3. สร้าง anomaly → **กดปุ่ม MARK ตอนเริ่ม** → ทำ → **กด MARK อีกครั้งตอนจบ**
   คอลัมน์ `label` ใน raw = `marked` ระหว่างสองครั้งนั้น · เฟิร์มแวร์เขียนเวลาเริ่ม/จบลง `EV_*.csv` บน SD ให้ (label = `marked`, note ว่าง)
4. จดลง `events/` ทันที อย่ารอ
