# Dataset คุณภาพอากาศของไทย — สำหรับ AirGuard-S3

**สืบค้น:** 27 ก.ค. 2569

---

## ⚠️ อ่านก่อน — ข้อจำกัดที่ต้องเข้าใจตั้งแต่ต้น

**dataset ไทยทุกตัวข้างล่างนี้เป็นข้อมูล "นอกอาคาร" รายชั่วโมง และส่วนใหญ่มีแต่ PM**
ส่วนโปรเจกต์เราเป็น **ในอาคาร · 1 Hz · 7 ช่องสัญญาณ**

| | Dataset ไทย | โปรเจกต์เรา |
|---|---|---|
| สถานที่ | นอกอาคาร | **ในห้อง** |
| ความถี่ | รายชั่วโมง | **1 Hz (3,600 เท่า)** |
| ช่องสัญญาณ | PM2.5, PM10 (+ temp/RH บางแหล่ง) | **7+ ช่อง มี TVOC, eCO₂, CO** |
| Anomaly ที่สนใจ | มลพิษระดับเมือง | **จุดธูป กวาดบ้าน สเปรย์ เซนเซอร์พัง** |

### ✅ ใช้ทำอะไรได้จริง
1. **ซ้อม pipeline ช่วง 20 วันที่ยังไม่มีฮาร์ดแวร์** — load → window → train AE → quantize → วัดผล
2. **บริบทฤดูกาลไทย** — รู้ว่าฤดูเผา/ฤดูฝนหน้าตาข้อมูลต่างกันแค่ไหน
3. **🔑 เป็น feature จริงในระบบ** (ดู §5 — ข้อนี้สำคัญที่สุด)
4. **ตัวอย่าง sensor fault จริง** สำหรับ pre-train ตัวตรวจ fault (คลาส B)

### ❌ ใช้ทำไม่ได้
- **ใช้เป็น training set ของโมเดลที่ deploy จริงไม่ได้** — distribution คนละเรื่องกันเลย
- อย่าเขียนในรายงานว่า "train ด้วยข้อมูล Air4Thai แล้วเอาไปใช้ในห้อง" เพราะมันไม่ถูกต้องเชิงวิธีวิทยา

## 1. ⭐ DustBoy / CMU CCDC — ตรงกับโปรเจกต์เรามากที่สุด

**เว็บ:** `cmuccdc.org` · **API:** `open-api.cmuccdc.org`

| | |
|---|---|
| ผู้ดูแล | ศูนย์ข้อมูลการเปลี่ยนแปลงสภาพภูมิอากาศ ม.เชียงใหม่ (CCDC) |
| จำนวนจุด | 400+ จุดทั่วไทย (มีแผนขยายเป็น 2,000–3,000) |
| ข้อมูล | **PM2.5, PM10, อุณหภูมิ, ความชื้น, ปริมาณน้ำฝน** |
| ความถี่ | รายชั่วโมง |
| ย้อนหลัง | **30 วัน / 1 ปี / 5 ปี** (ตามสิทธิ์บัญชี) |
| ค่าใช้จ่าย | ฟรี ต้องลงทะเบียน |

### 🔑 ทำไมตัวนี้ดีที่สุดสำหรับเรา
1. **เป็นเซนเซอร์ราคาประหยัดคลาสเดียวกับเรา** ไม่ใช่เครื่องมือ reference-grade
   → มี noise, drift, และ fault แบบเดียวกับที่ PMS7003 ของเราจะเจอ
2. **มี PM2.5 + PM10 + อุณหภูมิ + ความชื้นครบ** → คำนวณ **PM2.5/PM10 ratio** และทดสอบ **RH confound** ได้เลย
   ซึ่งเป็น 2 feature สำคัญที่สุดในแผนของเรา
3. ย้อนหลังได้ถึง 5 ปี → เห็น seasonal drift และ sensor degradation ระยะยาว

### วิธีขอ API key
```
1. ไป https://open-api.cmuccdc.org/#account → ลงทะเบียน
2. เลือกหน่วยงานสังกัด = "นักศึกษา นักวิจัย"   ← ได้สิทธิ์มากกว่าประชาชนทั่วไป
3. เลือกวัตถุประสงค์ = "งานวิจัย"
4. ยืนยันอีเมล → รอแอดมินอนุมัติ (ประเภทนักศึกษาต้องรออนุมัติ)
5. ได้ API key → เรียกผ่าน header: Authorization: Bearer {your_api_key}
```

⏰ **ลงทะเบียนวันนี้** เพราะต้องรอแอดมินอนุมัติ — อย่ารอถึงวันที่จะใช้

### Endpoints ที่ใช้บ่อย
| Endpoint | ได้อะไร |
|---|---|
| `GET /api/dustboy/stations` | รายชื่อจุดติดตั้งทั้งหมด + ค่าล่าสุด |
| `GET /api/dustboy/nearme/{lat}/{lon}/{dist}` | จุดใกล้พิกัด (รัศมีสูงสุด 20 กม.) — **ใช้หาสถานีใกล้ศรีราชา** |
| `GET /api/dustboy/data30day/{id}` | ย้อนหลัง 30 วันของจุดนั้น |
| `GET /api/dustboy/data1year/{id}` | ย้อนหลัง 1 ปี |
| `GET /api/dustboy/data5year/{id}` | ย้อนหลัง 5 ปี |
| `GET /api/dustboy/database/{yyyy}{mm}` | ทุกจุด รายเดือน เช่น `202601` |

### ⚠️ ข้อควรรู้
- **ประชาชนทั่วไปดึงได้สูงสุด 10 จุดต่อบัญชี** — บัญชีนักศึกษา/นักวิจัยได้สิทธิ์มากกว่า
- 🔑 **API ให้เฉพาะจุดติดตั้ง "นอกอาคาร" เท่านั้น**
  แต่เอกสารระบุว่า **ข้อมูลในอาคาร (Indoor) ขอเป็นรายกรณีได้** →
  **ทีมควรลองส่งอีเมลขอ** (`dustboy.3e@gmail.com`) โดยอธิบายว่าทำโปรเจกต์ indoor air quality
  ถ้าได้มา จะเป็นข้อมูลที่ตรงกับโปรเจกต์เราที่สุดในบรรดาทั้งหมด
- **ต้องอ้างอิงแหล่งที่มา** ทุกครั้งที่นำไปแสดง เช่น
  *"ข้อมูลจากเครื่องตรวจวัดคุณภาพอากาศ DustBoy — ศูนย์ข้อมูลการเปลี่ยนแปลงสภาพภูมิอากาศ มหาวิทยาลัยเชียงใหม่ (CCDC CMU)"*
  ถ้าไม่อ้างอิง เขาสงวนสิทธิ์ระงับการเข้าถึงโดยไม่แจ้งล่วงหน้า
- ⚠️ ในหน้าเว็บมีลิงก์ดาวน์โหลดรายเดือนตั้งแต่ 2023–2026 แต่**ลิงก์ทั้งหมดชี้ไป `202412` เหมือนกันหมด**
  (น่าจะเป็นบั๊กของเว็บ) → **ให้ประกอบ URL เองตามรูปแบบ `/api/dustboy/database/{yyyy}{mm}`**

## 2. Air4Thai / กรมควบคุมมลพิษ — ข้อมูลอ้างอิงระดับทางการ

**เว็บ:** `air4thai.pcd.go.th/webV3/` · **Catalog:** `envilink.go.th`

| | |
|---|---|
| ผู้ดูแล | กองจัดการคุณภาพอากาศและเสียง กรมควบคุมมลพิษ |
| ข้อมูล | **PM2.5, PM10, O₃, CO, NO₂, SO₂** + AQI |
| ความถี่ | รายชั่วโมง (บางสถานี) และรายวัน |
| ย้อนหลังบนเว็บ | กราฟ 7 วัน |
| ย้อนหลังจำนวนมาก | ผ่าน **Envilink Data Catalog** (`envilink.go.th`) — JSON / XML |

### ใช้ทำอะไร
- ✅ เป็น **ค่าอ้างอิงคุณภาพสูง** (สถานีมาตรฐาน ไม่ใช่เซนเซอร์ราคาถูก)
- ✅ มี **ก๊าซครบ 6 ชนิด** ซึ่ง DustBoy ไม่มี
- ✅ ใช้เทียบว่าเซนเซอร์ราคาถูกอ่านต่างจากเครื่องมาตรฐานแค่ไหน — เป็นหัวข้อ calibration ที่ดี

⚠️ เว็บ Envilink เป็น JavaScript-heavy — ถ้า `curl` แล้วได้หน้าเปล่า ให้เปิดในเบราว์เซอร์แล้วหาลิงก์ API/ไฟล์จริง

### 📐 เกณฑ์ AQI ไทยที่ใช้ตั้ง threshold ได้เลย
| AQI | PM2.5 24 ชม. (µg/m³) | PM10 24 ชม. | ความหมาย | LED ของเรา |
|---|---|---|---|---|
| 0–25 | 0–15.0 | 0–50 | ดีมาก | 🟢 |
| 26–50 | 15.1–25.0 | 51–80 | ดี | 🟢 |
| 51–100 | 25.1–37.5 | 81–120 | ปานกลาง — **กลุ่มเสี่ยงเริ่มมีอาการ** | 🟡 |
| 101–200 | 37.6–75.0 | 121–180 | มีผลกระทบต่อสุขภาพ | 🔴 |
| >200 | >75.1 | >180 | มีผลกระทบมาก | 🔴 + บี๊บ |

🔑 **ใช้ตรงกับโปรเจกต์:** ตารางนี้ map เป็นสี LED 3 ดวงของเราได้ทันที และ**แถว 51–100 คือแถวที่สำคัญที่สุดสำหรับคนภูมิแพ้**
เพราะเป็นช่วงที่ "ประชาชนทั่วไปปกติดี แต่กลุ่มเสี่ยงเริ่มมีอาการ" — ตรงกับ use case ของเราเป๊ะ

## 3. OpenAQ — เข้าถึงง่ายที่สุดเชิงโปรแกรม

**เว็บ:** `explore.openaq.org` · **API docs:** `docs.openaq.org`

- รวบรวมข้อมูลจากทั่วโลก **ข้อมูลไทยมาจากกรมควบคุมมลพิษ**
- **API มี documentation ดีที่สุดในบรรดาทั้งหมด** filter ตาม location / parameter / ช่วงวันที่ได้
- ดาวน์โหลดผ่าน Explorer ได้หลัง login
- มีสถานีในกรุงเทพหลายจุด (เช่น ตลิ่งชัน, ถ.อินทรพิทักษ์, ถ.พระราม 4)

✅ **แนะนำให้เริ่มจากตัวนี้ถ้าอยากได้ข้อมูลเร็วที่สุดโดยไม่ต้องรออนุมัติ**
❌ แต่ข้อมูลก็คือ PCD ที่ผ่านการ normalize มาแล้ว ไม่ได้เพิ่มอะไรจาก Air4Thai นอกจากความสะดวก

## 4. Sensor.Community Archive — ⭐ ดีสำหรับ "sensor fault"

**Archive:** `archive.sensor.community` · **ทางเลือก:** `api-rrd.madavi.de/csvfiles.php`

- เครือข่ายเซนเซอร์ภาคประชาชนทั่วโลก 35,000+ จุด **มีจุดในไทยรวมถึงกรุงเทพ**
- **export เป็น CSV วันละครั้ง (ราว 8:00 น.) — 1 ไฟล์ต่อ 1 เซนเซอร์ต่อ 1 วัน**
- เซนเซอร์ที่ใช้ส่วนใหญ่คือ **SDS011 / Plantower** = ตระกูลเดียวกับ PMS7003 ของเรา
- มีเครื่องมือ scrape สำเร็จรูป: `github.com/CGodiksen/sensor-community-data`

### 🔑 ทำไมตัวนี้มีค่าเป็นพิเศษ
**ข้อมูลนี้เป็นข้อมูลดิบที่ยังไม่ผ่านการกรอง** → มี **sensor fault จริงปนอยู่**
(ค่าค้าง · ค่ากระโดด · ข้อมูลขาด · เซนเซอร์ตาย)
→ ใช้ **pre-train หรือ validate ตัวตรวจจับ fault (คลาส B ใน §03 ของแผน)** ได้โดยไม่ต้องรอให้เซนเซอร์เราพังเอง

⚠️ ไม่มีการรับประกันคุณภาพหรือ metadata ที่ครบถ้วน — ต้อง clean เองเยอะ

## 5. 🔑 การใช้ที่คุ้มที่สุด — Indoor/Outdoor Ratio (ทำเป็น feature จริง)

<u>นี่คือไอเดียที่ควรทำจริง ไม่ใช่แค่เอา dataset มาซ้อม</u>

ดึง PM2.5 **นอกอาคาร** จากสถานี DustBoy/Air4Thai ที่ใกล้ที่สุด (ผ่าน `nearme` API)
แล้วคำนวณเทียบกับค่า**ในห้อง**ของเรา:

```
I/O ratio = PM2.5_ในห้อง / PM2.5_นอกอาคาร
```

| I/O ratio | แปลว่า | คำแนะนำให้ผู้ป่วยภูมิแพ้ |
|---|---|---|
| **≈ 1** | อากาศในห้องตามข้างนอก | หน้าต่าง/ประตูรั่ว หรือเปิดอยู่ → **ปิดหน้าต่าง** |
| **< 0.5** | ห้องกรองได้ดี | ✅ ปลอดภัย อยู่ในห้องต่อได้ |
| **> 1.5** | 🔴 **แหล่งกำเนิดอยู่ในห้อง** | จุดธูป? ทำอาหาร? ฝุ่นฟุ้ง? → **ต้องหาต้นตอในห้อง ไม่ใช่ปิดหน้าต่าง** |

### ทำไมถึงสำคัญมาก
1. **แก้ปัญหา contextual anomaly ได้ตรงจุด** — PM2.5 = 60 ตอนฤดูเผาป่าไม่ใช่เรื่องผิดปกติ
   แต่ถ้าข้างนอก 20 แล้วในห้อง 60 → **ผิดปกติแน่นอน** มีแหล่งกำเนิดในห้อง
2. **ให้คำแนะนำที่ใช้ได้จริงกับผู้ป่วย** — "ปิดหน้าต่าง" กับ "หาต้นตอในห้อง" เป็นคำแนะนำตรงข้ามกัน
   ถ้าแนะนำผิดจะยิ่งแย่ (ปิดหน้าต่างทั้งที่ต้นตออยู่ในห้อง = อาการหนักขึ้น)
3. **เป็นสิ่งที่เครื่องวัดฝุ่นเชิงพาณิชย์ไม่ทำ** → จุดขายของโปรเจกต์
4. เพิ่ม feature ให้โมเดลโดยแทบไม่เพิ่มต้นทุนฮาร์ดแวร์ (แค่เรียก API)

⚠️ **ข้อจำกัดที่ต้องเขียนในรายงาน:** สถานีนอกอาคารที่ใกล้ที่สุดอาจห่างหลายกิโลเมตร
และเป็นข้อมูล**รายชั่วโมง**ขณะที่เราวัดทุกวินาที → ต้อง interpolate และระบุว่าเป็น proxy ไม่ใช่ค่าจริงหน้าบ้าน

## สิ่งที่ต้องจำ

- 🔴 **ลงทะเบียน DustBoy API วันนี้** — บัญชีนักศึกษาต้องรอแอดมินอนุมัติ อย่ารอถึงวันที่จะใช้
- **DustBoy ดีที่สุดสำหรับเรา** เพราะเป็นเซนเซอร์ราคาถูกคลาสเดียวกัน และมี PM2.5+PM10+T+RH ครบ
- **ลองอีเมลขอข้อมูล indoor จาก CCDC** (`dustboy.3e@gmail.com`) — เอกสารระบุว่าขอเป็นรายกรณีได้
- **Sensor.Community มี sensor fault จริงปนอยู่** → ใช้ฝึกตัวตรวจ fault โดยไม่ต้องรอเซนเซอร์เราพัง
- **ตาราง AQI ไทย map เป็นสี LED ได้ทันที** และแถว 51–100 คือแถวของคนภูมิแพ้
- 🔑 **I/O ratio คือการใช้ dataset ไทยที่คุ้มที่สุด** — แยก "มลพิษจากข้างนอก" ออกจาก "แหล่งกำเนิดในห้อง"
  ซึ่งนำไปสู่คำแนะนำที่ตรงข้ามกันโดยสิ้นเชิงสำหรับผู้ป่วย
- ⚠️ **ห้ามเขียนว่า train ด้วยข้อมูลนอกอาคารแล้วเอาไปใช้ในห้อง** — distribution คนละเรื่อง ผิดวิธีวิทยา
- **ต้องอ้างอิงแหล่งที่มาทุกครั้ง** โดยเฉพาะ DustBoy ที่มีเงื่อนไขชัดเจน
