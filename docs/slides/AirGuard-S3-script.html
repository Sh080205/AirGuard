  • อย่าอ้างว่าแยกสองเหตุการณ์นี้ได้แล้ว — ยังไม่ได้ทดสอบบนข้อมูลจริง

7. Pull-up · pull-down · การปรับสัญญาณ

Circuit · Schematic · PCB · PCBA · เริ่ม 2:50 · ยาว 0:40 · 7.1 ตัวอักษร/วินาที
บทพูด · ผู้พูดแนะนำ: A · ฮาร์ดแวร์

บนบอร์ดไม่มี pull-up ของปุ่ม จึงเปิด pull-up ภายใน พร้อม RC กรองเด้ง 4.52 มิลลิวินาที และ debounce ในซอฟต์แวร์ 50 มิลลิวินาที
I²C ใช้ pull-up ภายนอก 4.7 กิโลโอห์มไป 3.3 โวลต์ gate ของ MOSFET ที่ขับ buzzer มี pull-down 100 กิโลโอห์ม กันเสียงดังเองตอนบูต
และขา TX ไป ZE07 มีตัวต้านทาน 100 โอห์ม เพราะ ZE07 รับลอจิกได้แค่ 3.0 โวลต์

  • ปุ่ม: τ = (45 000 + 220) × 100 nF = 4.52 ms · ในโค้ด tasks_io.c:564 เปิด GPIO_PULLUP_ENABLE และจับขอบลง (NEGEDGE)
  • I²C: ปิด pull-up ภายใน (enable_internal_pullup = false) เพราะ 45 kΩ อ่อนเกินสำหรับ rise time และมี 4.7 kΩ ภายนอกแล้ว · ห้ามจ่ายโมดูลด้วย 5 V
  • Q1: VGS(on) = 3.3 × 100k/101k = 3.27 V
  • R4: ไดโอดป้องกันของ ZE07 จะนำกระแส R4 จำกัดไว้ราว 3 mA
  • ถูกถาม "ทำไมปุ่มใช้ pull-up?" → ปุ่มต่อลงกราวด์ กดแล้วเป็น 0 จับขอบลง
  • ถูกถาม "R10 มีไว้ทำอะไร?" → pull-down ที่ gate ของ Q1 กัน buzzer ดังเองตอนบูต

11. เส้นทางความปลอดภัย CO

Firmware · Sensor · Actuator · เริ่ม 5:55 · ยาว 0:30 · 7.5 ตัวอักษร/วินาที
บทพูด · ผู้พูดแนะนำ: B · เฟิร์มแวร์

เส้นทาง CO แยกจากทุกอย่าง ใช้เกณฑ์ WHO ค่าทันที 90 ppm หรือเฉลี่ยหนึ่งชั่วโมง 30 ppm ถ้าเซนเซอร์เงียบเกินหกวินาทีขึ้น FAULT
ไม่พึ่ง ML, SD หรือ Wi-Fi ข้อจำกัดคือ ALARM ยังทดสอบด้วย host test เท่านั้น
[ส่งต่อ] ต่อไป [ชื่อ C] จะเล่าว่าข้อมูลออกไปถึงผู้ใช้และโมเดลอย่างไร

  • เกณฑ์มาจากแนวทาง WHO ในอาคาร (docs/03 §2): 90 ppm เป็นค่าเฉลี่ย 15 นาที · ใช้ค่าทันทีจึงเข้มกว่า · 30 ppm ค่าเฉลี่ย 1 ชม.
  • ออกจาก ALARM ต้องต่ำกว่าเกณฑ์ลบ 10% ต่อเนื่อง (hysteresis) กันไฟกะพริบเข้าออกรอบเกณฑ์
  • ถูกถาม "ถ้า Wi-Fi พัง CO ยังเตือนไหม?" → ยังเตือน เส้นทาง CO ไม่พึ่ง Wi-Fi/SD/ML และเริ่มก่อนทุกอย่างตอนบูต
  • ห้ามพูดตัวเลข latency ของ CO — ยังไม่ได้วัด

23. สถาปัตยกรรม task (ESP-IDF + FreeRTOS)

เฟิร์มแวร์ใช้ ESP-IDF กับ FreeRTOS แบ่งงานเป็น task ตามความเร่งด่วน

  • co กับ sampler pin core 1 · Wi-Fi/lwIP อยู่ core 0 ที่ priority สูงกว่า
  • ถ้า storage/sampler init พัง ไม่ abort เพราะ abort จะ reboot วนและพาเส้นทาง CO ล่มไปด้วย

25. 1 วินาทีของ sampler และผลวัดเวลา

  • GPIO4 HIGH ตอนเริ่มรอบ LOW ตอนจบ — ใช้ logic analyzer วัดคาบและเวลาทำงานได้
  • งาน ~113 ms เกิดตอนไม่มีจอด้วย จึงไม่ได้มาจากจอ · สาเหตุยังไม่ทราบ · ไม่มี overrun
  • 608 แถวใน 610 s: นับรวมช่วงต้น/ท้ายของหน้าต่างวัด เท่ากันทั้งสองชุด
