## 1. ภาพรวมบอร์ด

**หน้าที่:** carrier board สำหรับเสียบโมดูล ESP32-S3-DevKitC-1 แล้วต่อเซนเซอร์คุณภาพอากาศ
เพื่อเก็บข้อมูลและรัน anomaly detection บนอุปกรณ์

**สิ่งที่บอร์ดนี้ *ไม่* มี** — เพราะ DevKitC มีอยู่แล้วบนตัวมันเอง:
USB · ตัวควบคุมแรงดัน 3.3 V · วงจร EN/RC · pull-up ของ GPIO0 · ปุ่ม BOOT/RESET · ฟิวส์ · TVS

```
                    ┌─────────────────────────────┐
   5 V adapter ────▶│  +5V rail ──┬──▶ J1 PMS7003 │
                    │             ├──▶ J2 ZE07-CO │
                    │             └──▶ U1 pin 21  │
                    │                             │
                    │  U1 = ESP32-S3-DevKitC-1    │
                    │   (เสียบบน socket 2×22)      │
                    │      │                      │
                    │      ├─ 3V3 ──▶ I²C, SD     │
                    │      ├─ UART1 ──▶ J1        │
                    │      ├─ UART2 ──▶ J2        │
                    │      ├─ I²C ────▶ J3 J4 J5  │
                    │      ├─ SPI ────▶ J6        │
                    │      └─ GPIO ───▶ LED ปุ่ม   │
                    └─────────────────────────────┘
```

### 3.3 ตัวต้านทาน — **0805 ทั้งหมด · 15 ตัว**

| Des | ค่า | หน้าที่ | กระแส/ค่าที่ได้จริง |

| R4 | 100 Ω | อนุกรมสาย ESP TX → ZE07 RX | ดูคำเตือนข้อ 6.3 |
| R5 | **220 Ω** | จำกัดกระแส LED1 | ≈ 5.9 mA @ Vf 2.0 V |
| R6 | **220 Ω** | จำกัดกระแส LED2 | ≈ 5.9 mA @ Vf 2.0 V |
| R7 | **220 Ω** | จำกัดกระแส LED3 | ≈ 5.9 mA @ Vf 2.0 V |
| R8 | **470 Ω** | จำกัดกระแส LED4 (ไฟเข้า, ราง **5 V**) | ≈ 4.3 mA @ Vf 3.0 V |
| R9 | 1 kΩ | อนุกรม gate ของ Q1 | |
| R10 | **100 kΩ** | pull-down gate ของ Q1 | Vgs(on) ≈ 3.27 V |
| **R11** | **220 Ω** | 🆕 อนุกรมป้องกัน GPIO ปุ่ม MARK | I_max 15 mA |
| **R12** | **220 Ω** | 🆕 อนุกรมป้องกัน GPIO ปุ่ม MODE | I_max 15 mA |
| **R13** | **220 Ω** | 🆕 อนุกรมป้องกัน GPIO ปุ่ม ACK | I_max 15 mA |
| **R14** | **1 kΩ** | 🆕 อนุกรม U0TXD → J7 | กัน backfeed จาก USB-TTL |
| **R15** | **1 kΩ** | 🆕 อนุกรม J7 → U0RXD | กัน backfeed จาก USB-TTL |

> **ทำไม R10 เป็น 100 kΩ ไม่ใช่ 10 kΩ แล้วยังใช้ได้**
> ตอน GPIO สั่งสูง gate เห็นแรงดันจากตัวแบ่ง R9/R10:
> `Vgs = 3.3 × 100k/(100k+1k) = 3.27 V` — **สูงกว่าเดิม (10 kΩ ให้ 3.0 V)** เปิด MOSFET ได้เต็มกว่า
> ตอน GPIO ลอย (ช่วงบูต) กระแสรั่วของ gate 2N7002 ≤ 100 nA → `100k × 100n = 10 mV` ต่ำกว่า Vgs(th) มาก → ปิดสนิท
> ตอนปิด: ถ้า GPIO ขับต่ำ R9 (1 kΩ) คายประจุใน ~50 ns · ถ้า GPIO ลอย R10 คายใน ~5 µs
> **buzzer แบบ active ขับด้วย DC on/off ไม่ใช่ PWM ความถี่สูง → 5 µs ไม่มีผล** ✅ ผ่าน

> **🆕 ทำไม R11–R13 เป็นของดีที่เพิ่มเข้ามา**
> ถ้าเฟิร์มแวร์ตั้ง GPIO ปุ่มเป็น output-high โดยพลาด แล้วมีคนกดปุ่ม → GPIO ต่อตรงลง GND
> ไม่มี R = กระแสถูกจำกัดด้วยความต้านทานภายในของไดรเวอร์เท่านั้น **ขาพังได้**
> มี R = `3.3 V / 220 Ω = 15 mA` ต่ำกว่าพิกัด 40 mA ของ ESP32 ✅

> ### 🟠 C13 — ตัวที่เพิ่มมาใหม่และต้องคิดก่อนสั่ง
>
> **ทำไมมันช่วย** — ราง 3.3 V มีโหลดที่กระชากเป็นช่วง คือ **การเขียน microSD** (พีคได้ ~100 mA)
> LDO ไม่ได้ตอบสนองทันที มันใช้เวลาประมาณ 50 µs กว่าจะปรับกระแสตาม
> ช่วงนั้นตัวเก็บประจุต้องจ่ายแทน:
>
> ```
> ΔV = I × Δt / C        ← สูตรพื้นฐานของตัวเก็บประจุ
>
> มีแค่ C4 (10 µF):    ΔV = 0.1 A × 50 µs / 10 µF  = 500 mV  ❌ มากเกินไป
> มี C13 ด้วย (480 µF): ΔV = 0.1 A × 50 µs / 480 µF = 10 mV   ✅ ดีมาก
> ```
>
> ✅ **เหตุผลนี้ฟังขึ้น เก็บ C13 ไว้ได้** — แต่ต้องเช็ค 2 ข้อในข้อ 6.10 ก่อนสั่ง

> ### 🔑 U1 คืออะไรกันแน่
>
> footprint `U1` ให้แค่ **รู THT 44 รู** ไม่ได้แถมชิ้นส่วนมาด้วย → ต้องซื้อ 2 อย่างแยกกัน

> ⚠️ **1×22 ไม่ใช่ขนาดมาตรฐาน** — ต้องซื้อ 1×40 มาตัด และจะเสียตำแหน่งที่ตัดไป 1 ช่อง

> ### 🔑 ทำไมเน็ตเยอะขึ้นจาก 20 เป็น 37
>
> **ทุกครั้งที่แทรกตัวต้านทานอนุกรม เน็ตหนึ่งเส้นจะถูกผ่าเป็นสองเส้น**
>
> ```
> ก่อน:   U1.39 ────────────── SW1        = 1 เน็ต (BTN_MARK)
>
> หลัง:   U1.39 ── R11 ── SW1
>          └BTN_MARK┘  └BTN_MARK_S┘        = 2 เน็ต
> ```
>
> ต่อท้าย `_S` = **ฝั่ง Sensor/Switch** คือด้านนอกของตัวต้านทาน (ด้านที่ต่อโลกภายนอก)
> ไม่ต่อท้าย = ด้านที่ต่อขา ESP32 โดยตรง
> `_A` = **Anode** ของ LED
>
> 📌 **ประโยชน์ตอนไล่บั๊ก:** เห็นชื่อเน็ตแล้วรู้ทันทีว่ากำลังวัดด้านไหนของตัวต้านทาน
> เช่นวัด `BTN_MARK` ได้ 3.3 V แต่ `BTN_MARK_S` ได้ 0 V → R11 ขาดหรือบัดกรีไม่ติด

## 6. วงจรทีละบล็อก

### 6.1 ⚡ ไฟเลี้ยง

```
U1.21 (5V) ──┬── NET:+5V ──┬── J1.1, J1.2   (PMS7003 VCC)
             │             ├── J2.1          (ZE07-CO Vin)

             │             ├── TP6           (test point)

### 6.7 🔴 Buzzer + MOSFET

```
        +3V3
         │
    ┌────┴────┐
    │         │
  BZ1.2    D1.1 = แคโทด (ด้านมีแถบคาด)
    │         │
  BZ1.1 ─────┴──── D1.2 = แอโนด     ← เน็ต BUZZ_DRV
    │
  Q1.3 (drain)
    │
  Q1.2 (source) ──── GND

  U1.38 ── R9 (1 kΩ) ── Q1.1 (gate)   ← เน็ต BUZZ_G
       └BUZZ┘             │
                       R10 (100 kΩ)
                          │
                         GND
```

| เน็ต | สมาชิก (จาก netlist) |
|---|---|
| `+3V3` | **BZ1.2**, **D1.1 (แคโทด)** |
| `BUZZ_DRV` | **BZ1.1**, **D1.2 (แอโนด)**, Q1.3 |
| `BUZZ` | U1.38, R9.1 |
| **`BUZZ_G`** 🆕 | R9.2, R10.1, Q1.1 |
| `GND` | R10.2, Q1.2 |

> 🔴 **ทิศทาง D1 ผิดไม่ได้** — แคโทด (ขามีแถบ) ต้องอยู่ด้าน `+3V3`
> ถ้ากลับด้าน จะลัด 3.3 V ลง drain ตลอดเวลา → Q1 ไหม้
> `[ต้องไปเช็คเอง]` เปิด symbol 1N4148W ใน EasyEDA ยืนยันว่า **pin 1 = cathode**
> ถ้าไลบรารีกำหนด pin 1 = anode ต้องกลับด้านทั้งหมด

> ### 🔴 ขั้ว buzzer — จุดที่ต้องเช็คก่อนบัดกรี
>
> netlist ปัจจุบันคือ **BZ1.2 → +3V3** และ **BZ1.1 → drain ของ Q1**
>
> ```
> กระแสไหล:  +3V3 ──▶ BZ1.2 ──▶ BZ1.1 ──▶ drain ──▶ GND
> ```
>
> ⚠️ **buzzer แบบ active magnetic ส่วนใหญ่มีขั้ว** — ขา + ต้องรับไฟบวก
> ถ้า footprint `BUZ-TH_BD12.0-P6.00-D0.9-RD` กำหนดให้ **pin 1 = +** แสดงว่าตอนนี้**ต่อกลับขั้ว**
>
> **อาการถ้ากลับขั้ว:** ไม่ดัง หรือดังเบามาก — ไม่ระเบิด ไม่ไหม้ แต่ตามหาสาเหตุยาก
>
> `[ต้องวัดจริง]` **วิธีตรวจใน 30 วินาที:** เอา buzzer ที่ซื้อมาต่อกับถ่าน 3 V ตรงๆ
> ลองทั้งสองทาง จำว่าทางไหนดัง → เทียบกับ pin 1 ในไลบรารี → แก้ schematic ถ้าไม่ตรง

> 🔑 **R10 จำเป็น** — ถ้าไม่มี ตอนบูต gate จะลอยและ buzzer อาจดังเอง
> ค่า 100 kΩ ที่ใช้จริงยังทำหน้าที่ได้ครบ — เหตุผลอยู่ในตารางข้อ 3.3

> ### 🔴 บังคับสำหรับเฟิร์มแวร์ — **ไม่มี pull-up ภายนอกบนบอร์ด**
>
> ```c
> // ถ้าลืมบรรทัด pull_up_en ปุ่มจะอ่านค่ามั่วทั้งหมด

> };

> ```
>
> **อาการถ้าลืม:** ปุ่มอ่านได้บ้างไม่ได้บ้าง เปลี่ยนตามการเอามือเข้าใกล้บอร์ด

**การดีบาวซ์ด้วยฮาร์ดแวร์ — คำนวณจริง**

```
ตอนปล่อยปุ่ม: pull-up ภายใน (~45 kΩ) + R11 (220 Ω) ชาร์จ C10 (100 nF)

τ = (45 000 + 220) × 100 × 10⁻⁹ = 4.52 ms
เวลาถึงระดับลอจิกสูง ≈ 2τ ≈ 9 ms
```

|---|---|
| การเด้งของปุ่ม tact ทั่วไป | 1–5 ms |
| ค่าคงตัวเวลาของวงจรนี้ | 4.5 ms |
| ✅ สรุป | **กรองการเด้งได้ แต่ไม่ช้าจนคนรู้สึก** |

> ⚠️ `[ต้องวัดจริง]` ค่า pull-up ภายในของ ESP32-S3 อยู่ในช่วงกว้าง (~10–80 kΩ)
> ต้องเอาสโคปจับ waveform ที่ TP ตอนกดปุ่ม แล้ววัด τ จริง **ตัวเลขนี้ใส่ lab report ได้**
> ถ้าเด้งยังทะลุมา → เพิ่มดีบาวซ์ในซอฟต์แวร์ 20–50 ms ทับอีกชั้น

> 🔴 **ปุ่ม tact 4 ขา: ต้องเลือกขาที่อยู่คนละฝั่งกัน**
> ปุ่มมีขาลัดกันภายในเป็นคู่ ถ้าเลือกคู่ที่ลัดกันอยู่แล้ว = ปุ่มกดค้างตลอด
> ⚠️ **วัดด้วยมัลติมิเตอร์โหมด continuity ยืนยันก่อนวาง footprint**
> ขาที่ไม่ใช้ 2 ขา → วาง No Connect Flag

### 6.10 🟠 C13 บนราง 3.3 V — 2 ข้อที่ต้องเช็คก่อนสั่ง

**ปัญหาไม่ได้อยู่ที่ตัว C13 แต่อยู่ที่ว่ามันไปแขวนอยู่บนขาออกของ LDO ที่เราไม่ได้ออกแบบเอง**

```
   USB / J8         DevKitC-1 (ของ Espressif)          บอร์ดเรา
      5 V ───────▶ [ LDO ] ──────▶ 3.3 V ──▶ U1.1, U1.2 ──▶ C13 470 µF
                      ▲                                        C4 10 µF
                      │                                        C5 100 nF
                  เราไม่รู้ว่าเป็นเบอร์อะไร
```

#### ข้อ 1 — LDO รับความจุขาออกได้ถึง 470 µF ไหม

LDO ทุกตัวมี**ช่วงค่าความจุขาออกที่ทำให้วงจรป้อนกลับเสถียร** ระบุไว้ใน datasheet
ถ้าเกินช่วง อาการคือ **แรงดันขาออกแกว่งเอง (oscillation)** ซึ่งดูเหมือนสัญญาณรบกวนทั่วไป
ทำให้ ADC อ่านเพี้ยนและ WiFi หลุดเป็นระยะ — **ไล่บั๊กนี้ยากมากเพราะไม่มีอะไรพัง**

`[ขึ้นกับบอร์ด — ต้องเปิดเอกสาร]`
1. เปิด **ESP32-S3-DevKitC-1 User Guide** → หน้า schematic → หาเบอร์ LDO
2. เปิด datasheet ของ LDO ตัวนั้น → หัวข้อ **Output Capacitor** หรือ **Stability**
3. ดูว่า C_out สูงสุดที่ยอมรับได้เท่าไร

#### ข้อ 2 — กระแสไหลย้อนตอนปิดเครื่อง

```
ตอนปิดไฟ ราง 5 V มีโหลดหนัก (พัดลม PMS) → แรงดันตกเร็ว
        ราง 3.3 V มีโหลดเบา + C13 470 µF → แรงดันตกช้ากว่า

         V
         │╲                    ← 5 V ลงเร็ว
      5V ┤ ╲___
         │     ╲___
    3.3V ┤────────╲___         ← 3.3 V ลงช้า
         │    ▲    ╲
         └────┼─────────── t
              │
        ตรงนี้ V_out > V_in
        → กระแสไหลย้อนผ่านตัว LDO
```

LDO ส่วนใหญ่ไม่ได้ออกแบบให้รับกระแสย้อนทาง — datasheet มักมีหัวข้อ **Reverse Current** เตือนไว้

**ทางแก้ราคา ~3 บาท: ใส่ไดโอด Schottky คร่อม LDO**

| | ต่อที่ไหน |
|---|---|
| **แอโนด** | `+3V3` |
| **แคโทด** | `+5V` |

```
        ┌────── D2 (Schottky) ──────┐
        │  แอโนด            แคโทด   │
     +3V3                          +5V
```

- ตอนทำงานปกติ: `V_5V > V_3V3` → ไดโอด**ไบอัสกลับ ไม่นำกระแส** ไม่กวนอะไรเลย
- ตอนปิดเครื่อง: `V_3V3 > V_5V` → ไดโอด**นำกระแส** พากระแสอ้อม LDO ไป ✅

เบอร์ที่ใช้ได้: `SS14` หรือ `B5819W` (SOD-123) · `1N5819` (THT)

#### สรุปทางเลือก

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **A. เก็บ C13 + เพิ่ม D2 Schottky** ⭐ | ปิดความเสี่ยงทั้งสองข้อ | เพิ่ม 1 ชิ้น ~3 บาท |
| B. ลด C13 เหลือ 100 µF | ประจุสะสมลด 4.7 เท่า · ตัวเล็กลง | `ΔV = 50 mV` แทน 10 mV *(ยังโอเค)* |
| C. เก็บ 470 µF เฉยๆ | ไม่ต้องแก้อะไร | ⚠️ เสี่ยงถ้าไม่ได้เปิด datasheet ยืนยัน |
| D. ตัด C13 ทิ้ง | ง่ายที่สุด | ❌ SD card จะทำแรงดันตก 500 mV |

> 🔑 **ความเห็นเชิงสอน:** เลือก **A** — ราคาถูกกว่าเวลาที่จะเสียไปกับการไล่หา
> สาเหตุว่าทำไม ADC อ่านเพี้ยนเป็นบางครั้ง
> ถ้าเปิด datasheet ของ LDO แล้วพบว่ารับ 470 µF ได้และมีวงจรกันย้อนอยู่แล้ว → เลือก C ได้

>
> ตอนเซนเซอร์อ่านค่าไม่ได้ คำถามแรกคือ **"เซนเซอร์ไม่ส่ง หรือ ESP32 อ่านผิด"**

> เห็นข้อมูลที่ TP7  →  เซนเซอร์ปกติ   →  ปัญหาอยู่ที่โค้ด / baud rate
> ไม่เห็นอะไรเลย     →  เซนเซอร์ไม่ส่ง  →  ไปดูไฟเลี้ยง / สาย / PMS_SET
> ```
>
> 🔑 **นี่คือการแบ่งครึ่งปัญหาด้วยการวัดครั้งเดียว** — ตรงกับที่วิชา 03603324 ต้องการ
> คือ **หาสาเหตุด้วยการวัด ไม่ใช่เดาแล้วแก้โค้ดไปเรื่อยๆ**

> 🔑 **ตำแหน่งของ TP6 มีผลต่อค่าที่วัดได้** — วัดใกล้แหล่งจ่ายจะเห็นแรงดันตกน้อยกว่าความจริง
> วางไว้ใกล้จุดที่โหลดหนักที่สุด (พัดลม PMS) จึงจะได้ตัวเลขที่ตรงกับที่ ESP32 เจอ
>
> 📌 วาง TP กราวด์ **ห่างจาก TP สัญญาณ ≤ 10 mm** — ถ้าไกลกว่านี้ ลูปกราวด์ของ probe
> จะรับสัญญาณรบกวนเข้ามา ทำให้เห็น ringing ที่ไม่มีอยู่จริงบนสโคป

## 11. ลำดับบัดกรีหลังบอร์ดมาถึง

```
1. SMD 0805 ทั้งหมด + Q1 + D1     ← ตอนบอร์ดยังเรียบที่สุด ใช้ฟลักซ์เยอะ
2. 🔴 วัด +5V↔GND และ +3V3↔GND    ← ใกล้ 0 Ω = ช็อต หยุดหาสาเหตุก่อน
3. ปุ่ม SW1–SW3
4. คอนเนคเตอร์ J1–J8              ← ใช้เทปกาวยึดก่อนบัดกรีขาแรก
5. LED1–LED4                       ← ⚠️ ตรวจขั้ว ขายาว = บวก
6. 🔑 U1 socket (female header 2 เส้น)
       → เสียบ header ลงรู → **เสียบ DevKit ทับก่อน** → บัดกรีจากด้านล่าง
       → ถอด DevKit ออก แล้วบัดกรีที่เหลือ
       ⚠️ ถ้าบัดกรี header ลอยๆ แล้วเอียง DevKit จะเสียบไม่ลง
7. C1 + BZ1                        ← ⚠️ ตรวจขั้ว C1 และขั้ว BZ1 (ข้อ 6.7)
8. TP1–TP6                         ← 🆕 บัดกรีท้ายสุด ไม่บังทางหัวแร้ง
9. ล้างฟลักซ์ + ส่องแว่นขยายหาสะพานตะกั่ว
10. วัดความต่อเนื่องทุกเน็ตตามหัวข้อ 6
```

**🆕 หลังบัดกรีเสร็จ วัด 5 ค่านี้ก่อนจ่ายไฟ — ใช้มัลติมิเตอร์โหมดวัดความต้านทาน**

| วัดระหว่าง | ค่าที่ควรได้ | ถ้าไม่ตรง |
|---|---|---|
| TP6 (`+5V`) ↔ TP1 (`GND`) | ≫ 1 kΩ | 🔴 **ช็อต — หยุดทันที** |
| TP5 (`+3V3`) ↔ TP1 (`GND`) | ≫ 1 kΩ | 🔴 **ช็อต — หยุดทันที** |
| TP2 (`SDA`) ↔ TP5 (`+3V3`) | ≈ **4.7 kΩ** | R1 ไม่ติด หรือหยิบค่าผิด |
| TP3 (`SCL`) ↔ TP5 (`+3V3`) | ≈ **4.7 kΩ** | R2 ไม่ติด หรือหยิบค่าผิด |
| Q1 gate ↔ TP1 (`GND`) | ≈ **100 kΩ** | R10 ไม่ติด → **buzzer จะดังเองตอนบูต** |

> 🔑 **สองแถวล่างคือการใช้ TP พิสูจน์ว่าตัวต้านทานถูกค่าและบัดกรีติดจริง**

**ก่อนเสียบไฟครั้งแรก:** วัดว่าไม่ช็อต → จ่ายไฟโดยยังไม่เสียบ DevKit และเซนเซอร์ →
จับดูว่ามีอะไรร้อนผิดปกติ → เสียบ DevKit → **เสียบเซนเซอร์ทีละตัว** ไม่ใช่ทีเดียวหมด

### 15.5 🟠 C13 — ตอนนี้ตัดสินใจทีหลังได้ ไม่ต้องเดา

เพราะเป็น THT บัดกรีเอง เลยกลายเป็น **"ทดลองแล้วค่อยตัดสิน"** ซึ่งดีกว่าเดาล่วงหน้ามาก

```
รอบที่ 1  ไม่ใส่ C13  →  จ่ายไฟ  →  เอาสโคปจับที่ TP5 (+3V3)
          ┌─ สัญญาณนิ่ง ไม่แกว่ง            → LDO เสถียร ไปต่อ
          └─ แกว่งเป็นคลื่นเอง               → LDO มีปัญหาอยู่แล้ว ไม่ใช่เพราะ C13

รอบที่ 2  สั่งเขียน microSD ต่อเนื่อง  →  ดู TP5 ว่าแรงดันตกกี่ mV
          ┌─ ตก < 100 mV                    → ✅ ไม่ต้องใส่ C13 เลย
          └─ ตก > 200 mV                    → ใส่ C13 แล้ววัดซ้ำ

รอบที่ 3  ใส่ C13 แล้ว  →  ดู TP5 อีกครั้ง
          ┌─ นิ่งขึ้น แรงดันตกน้อยลง        → ✅ เก็บไว้
          └─ เริ่มแกว่ง / มี ringing         → 🔴 ถอดออก LDO รับไม่ไหว
```

> 🔑 **นี่คือรูปแบบที่วิชา 03603324 ต้องการเป๊ะ** — ตั้งสมมติฐาน → วัด → เทียบ → สรุป
> ตัวเลข ΔV ทั้งสามรอบใส่ lab report ได้ตรงๆ **มีค่ามากกว่าการใส่ C13 ไปเฉยๆ**
>
> ⚠️ ใส่ไดโอด Schottky กันกระแสย้อนไม่ได้แล้ว เพราะบอร์ดไม่มีรูไว้
> **ทางแก้ถ้าจำเป็นจริง:** บัดกรีคร่อมระหว่างขา C13 กับขา C1 ด้วยสายจัมเปอร์สั้น
> *(ไม่สวยแต่ใช้ได้ ถ้าเลือกไม่ใส่ C13 ก็ไม่ต้องทำเลย)*

### 15.6 🟠 LED1 เขียวอมเหลือง — แก้ด้วยเฟิร์มแวร์ ไม่ต้องแตะฮาร์ดแวร์
