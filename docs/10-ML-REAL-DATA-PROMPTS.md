## วิธีใช้ไฟล์นี้

1. เปิดแชตใหม่ (GPT หรือ Claude Code) **ต่องานหนึ่งขั้น**
2. วาง **§A ส่วนหัวร่วม** ตามด้วย prompt ของขั้นนั้น
3. ให้ผู้ทำทำจนครบ checkpoint แล้ว**หยุด** · เอารายงานไปให้ผู้รีวิว (คนละแชต) ตรวจ
4. เจ้าของโปรเจกต์อนุมัติ → commit/push เอง → ไปขั้นถัดไป

ระดับของ checkpoint:
- **CP-code** — pytest + ruff ผ่าน · ทำได้โดยไม่มีข้อมูล
- **CP-data** — ข้อมูลจริงผ่านเกณฑ์คุณภาพ · ทำโดยไม่ต้องเขียนโค้ดใหม่
- **CP-freeze** — ตัดสินใจที่ย้อนกลับไม่ได้ (feature · t1/t2 · threshold) · ต้องให้เจ้าของโปรเจกต์อนุมัติก่อนเดินต่อ

## R0 — ตัวตรวจคุณภาพข้อมูล `ml/qa.py` · CP-code

**ต้องรอ:** — · **branch:** `ml/r0-qa`

```text
งาน R0: เขียน ml/qa.py ตรวจคุณภาพไฟล์ raw §7 ก่อนนำไปเทรน · ต้องรันได้กับข้อมูลที่กำลังเก็บอยู่ทุกวัน

อ่านเพิ่ม: firmware/tools/serial_logger.py (ไฟล์ที่ได้) · CLAUDE.md §7 หมายเหตุ 3, 4, 14 ต.ค. (ค่าซ้ำที่ไม่ใช่บั๊ก)
          · CLAUDE.md §10 (PM ว่าง 30 s แรกหลังบูต · CO ว่าง 5 นาที · ENS160 ว่างช่วง warm-up)

ไฟล์ที่สร้าง/แก้ — เท่านี้: ml/qa.py · ml/tests/test_qa.py

CLI:
  python -m ml.qa --raw data/raw/usb_train/AG_*_usb.csv [--events data/events/<file>.csv] --out data/processed/qa/<วันที่>
โหลดด้วย ml.load.load_raw (ไม่เขียนตัวโหลดใหม่) · ถ้า load_raw error ให้แสดงชื่อไฟล์และบรรทัดที่ผิด แล้วจบด้วย exit code ≠ 0

สิ่งที่ต้องรายงาน (qa.json + qa.md สรุปให้คนอ่าน + รูป PNG):
1. ช่วงเวลารวม · จำนวนแถว · จำนวนแถวที่ควรมี (1 Hz) · % แถวหาย
2. ช่องว่างของเวลา: ตารางทุกช่องที่ > 1.5 s (เริ่ม · จบ · ยาว) และแยกว่าเป็น "รีบูต" (ตามด้วย PM ว่าง ~30 s) หรือ "หายระหว่างทาง"
3. ต่อคอลัมน์: % ว่าง แยกเป็น (ก) ช่วงอุ่นเครื่องหลังรีบูตที่ตั้งใจให้ว่าง (ข) ว่างนอกช่วงอุ่นเครื่อง
4. ค่าค้าง: ช่วงที่ค่าไม่เปลี่ยนเลยนานเกิน N นาที (ตั้งได้ · ค่าเริ่มต้น 10) · ห้ามนับค่าซ้ำ 2 แถวของ AHT21 และค่า PM ซ้ำ 2–3 แถวเป็นปัญหา
5. ช่วงค่าที่เป็นไปได้ทางกายภาพ (ระบุที่มาของขอบเขตทุกตัว เช่น RH 0–100) · ค่านอกช่วง = ธง ไม่ใช่ลบทิ้ง
6. label: จำนวนช่วง marked · ถ้ามี --events ให้ตรวจว่าช่วง marked ใน raw ตรงกับ events (คลาดเคลื่อนได้ ±2 s) และรายงานช่วงที่ไม่มีคู่
7. สถิติต่อวันของ pm2_5, temp_c, humidity_pct (median · p5 · p95) และ correlation matrix ของ pm_th บนแถว normal
8. รูป: time series ของ pm2_5 / temp_c / humidity_pct / tvoc_ppb / co_ppm แรเงาช่วง marked และช่องว่าง
9. ผลสรุปบรรทัดเดียว PASS / WARN / FAIL ตามเกณฑ์ใน CP0 ข้างล่าง (เกณฑ์ตั้งค่าได้ ใส่ไว้ใน dataclass เดียว)

ห้าม: แก้ไขหรือเขียนทับไฟล์ raw · impute ค่า · ลบแถว

test (ใช้ DataFrame/ไฟล์ที่สร้างใน test ไม่พึ่งข้อมูลจริง):
- ช่องว่าง 1 วินาทีไม่นับเป็น gap · 2 วินาทีนับ
- รีบูต (gap + PM ว่าง 30 s) แยกออกจากแถวหายระหว่างทาง
- ค่า AHT21 ซ้ำทุก 2 แถวไม่ถูกตั้งธงค่าค้าง · ค่าค้าง 11 นาทีถูกตั้งธง
- marked ใน raw ที่ไม่มีใน events ถูกรายงาน
- ไฟล์ raw ไม่ถูกแก้ (เทียบ hash ก่อน/หลัง)
- รันซ้ำได้ qa.json เหมือนเดิมทุกไบต์
```

**CP0 — ผ่านเมื่อ**
- [ ] `pytest ml/ -q` และ `ruff check ml/` ผ่าน (แปะผลจริง)
- [ ] รันกับไฟล์ USB ที่มีอยู่ (ข้อมูลนำร่องหรือข้อมูลวันแรก) แล้วได้ `qa.md` ที่อ่านรู้เรื่อง
- [ ] เกณฑ์ PASS/WARN/FAIL ที่เสนอ (ค่าคาดหมาย เจ้าของปรับได้): แถวหาย < 1 % · ไม่มีช่องว่างเดี่ยว > 10 นาทีในช่วง train · `pm2_5/temp_c/humidity_pct` ว่างนอกช่วงอุ่นเครื่อง < 1 %
