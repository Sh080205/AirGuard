# AirGuard-S3 — ทำอะไรต่อ

**อัปเดต:** 1 ก.ย. 2569 · **สถานะ:** schematic เสร็จ · สั่ง PCBA แล้ว (SMD ประกอบมา, THT บัดกรีเอง)

> ### 🎯 ทำไปทำไม — อ่านซ้ำเวลาหลงทาง
>
> **เครื่องเฝ้าระวังอากาศในห้องสำหรับผู้ป่วยภูมิแพ้และโรคทางเดินหายใจ
> ที่จับ "รูปแบบผิดปกติ" ไม่ใช่แค่ "ค่าเกินเกณฑ์"**
>
> เครื่องวัดที่มีขายเตือนเมื่อ PM2.5 เกินตัวเลข แต่สิ่งที่กระตุ้นอาการหลายครั้ง
> ไม่ได้ทำให้ค่าไหนเกินเกณฑ์เลย — **สิ่งที่เปลี่ยนคือความสัมพันธ์ระหว่างตัวแปร**
>
> ```
> ทำอาหาร   PM2.5↑ + อุณหภูมิ↑ + ความชื้น↑   → ขึ้นด้วยกัน = ปกติ
> ปัดฝุ่น/รา  PM2.5↑ แต่อุณหภูมิกับความชื้นนิ่ง → ความสัมพันธ์ขาด = ผิดปกติ
> ```
>
> ทั้งสองกรณี PM2.5 อาจเท่ากันเป๊ะ — **เกณฑ์ตัวเลขแยกไม่ออก แต่ multivariate แยกออก**
> นี่คือเหตุผลทั้งหมดที่ต้องมี autoencoder ไม่ใช่แค่ `if (pm25 > 50)`
>
> ดูเป้าหมายฉบับเต็มใน [`00-start-here/AirGuard-S3_TEAM_PLAN.md`](00-TEAM_PLAN.md)

```
1. เปิดไฟล์ PCB ใน EasyEDA → เครื่องมือ Measure
   วัดกึ่งกลางแพดแถวซ้าย → กึ่งกลางแพดแถวขวาที่อยู่ตรงข้าม     = _____ mm

2. หาค่าทางการมาเทียบ — เลือกทางใดทางหนึ่ง
   ก. เอาเวอร์เนียวัด DevKit ตัวจริง                            = _____ mm
   ข. เปิด DXF ทางการใน Autodesk Viewer แล้ววัดในนั้น           = _____ mm

3. ต่างกัน < 0.3 mm  →  ✅ ผ่าน
   ต่างกัน ≥ 0.5 mm  →  🔴 แก้ footprint แล้วสั่งใหม่
```

## 📦 พอบอร์ดมาถึง

### ขั้น 0 — ตรวจก่อนแตะหัวแร้ง (มัลติมิเตอร์อย่างเดียว)

| วัดระหว่าง | ควรได้ | ถ้าไม่ตรง |
|---|---|---|
| TP6 (+5V) ↔ TP1 (GND) | ≫ 1 kΩ | 🔴 ช็อต — เคลมโรงงาน |
| TP5 (+3V3) ↔ TP1 (GND) | ≫ 1 kΩ | 🔴 ช็อต — เคลมโรงงาน |
| TP2 (SDA) ↔ TP5 | ≈ 4.7 kΩ | R1 ไม่ติด |
| TP3 (SCL) ↔ TP5 | ≈ 4.7 kΩ | R2 ไม่ติด |
| gate ของ Q1 ↔ TP1 | ≈ 100 kΩ | R10 ไม่ติด → **buzzer ดังเองตอนบูต** |

**ส่องแว่นขยาย:** แถบคาดของ D1 ต้องอยู่ด้าน `+3V3` *(ถ้ากลับด้าน Q1 จะไหม้ตอนสั่ง buzzer)*

### ขั้น 1–6 — บัดกรี

```
1. U1 socket    🔑 เสียบ DevKit ทับก่อน ค่อยบัดกรีจากด้านล่าง — กันเอียง
2. J1–J8        ใช้เทปกาวยึดก่อนลงขาแรก
3. C1           ⚠️ ตรวจขั้ว +      · ยังไม่ต้องใส่ C13
4. BZ1          ⚠️ ตรวจขั้วก่อน ↓
5. จ่ายไฟโดยยังไม่เสียบ DevKit → จับดูว่ามีอะไรร้อนไหม
6. เสียบ DevKit → เสียบเซนเซอร์ทีละตัว ไม่ใช่ทีเดียวหมด
```

> 🔴 **หาขั้ว buzzer ก่อนบัดกรี** — ต่อกับถ่าน 3 V ลองทั้งสองทาง จำว่าทางไหนดัง
> บอร์ดเราต่อ **ขา 2 ไปไฟบวก** ถ้าของจริงขา 1 เป็นบวกต้องสลับ
> อาการถ้าผิด = ไม่ดังหรือดังเบามาก ไม่พังแต่หาสาเหตุนาน

## 🤔 2 เรื่องที่รอผลวัด ไม่ต้องตัดสินตอนนี้

### 🔴 C13 — **อย่าใส่** *(ตรวจ datasheet แล้ว 1 ก.ย. — กลับคำแนะนำเดิม)*

**ผมเคยแนะนำให้ใส่ C13 แล้วเพิ่มไดโอด Schottky — คำแนะนำนั้นผิด**
พอเปิด schematic ของ DevKit หาเบอร์ LDO จริงแล้ว ตัวเลขไม่ผ่าน

```
LDO บน DevKitC-1 = SGM2212-3.3XKC3G

datasheet · Recommended Operating Conditions:
    Output Effective Capacitance, COUT ......... 1 µF ถึง 10 µF

C13 ของเรา = 470 µF  →  เกินเพดาน 47 เท่า
```

และ datasheet เขียนกำกับไว้ตรงๆ ว่า
*"Functional operation of the device at any conditions beyond those indicated in the
Recommended Operating Conditions section is not implied."*
= ผู้ผลิต**ไม่รับรองว่าจะทำงานได้** ไม่ใช่แค่ "ไม่แนะนำ"

**ซ้ำร้าย DevKit มี C 10 µF บนราง 3.3 V อยู่แล้ว** → ตอนนี้อยู่ที่ขอบบนของช่วงพอดี ไม่มีที่ว่างให้เติม

#### แล้วปัญหาแรงดันตกตอน SD card เขียนล่ะ

ไม่มีจริงตั้งแต่แรก — **LDO ตัวนี้จ่ายได้ 800 mA** ส่วน ESP32-S3 พีคตอน WiFi TX ~350 mA
และ microSD ~100 mA · datasheet โฆษณาว่า *"fast transient response"* โดยเฉพาะ

| ทำ | ผล |
|---|---|
| **ไม่ใส่ C13** ⭐ | ✅ อยู่ในสเปกผู้ผลิต · ประหยัด 1 ชิ้น · ไม่ต้องทำอะไรเลย |
| ใส่ 470 µF | 🔴 นอกสเปก 47 เท่า · เสี่ยงแกว่ง + กระแสย้อนตอนปิดเครื่อง |
| ใส่ 4.7–10 µF แทน | 🟡 อยู่ในสเปก แต่ **ได้ประโยชน์น้อยมาก** เพราะ DevKit มีให้แล้ว |

> 🔑 **ยังวัดเก็บเป็น lab report ได้** — เอาสโคปจับ TP5 ตอนสั่งเขียน microSD ต่อเนื่อง
> วัด ΔV ที่เกิดจริง แล้วเทียบกับ 800 mA ที่ LDO จ่ายได้
> **"เราคิดว่าต้องใส่ bulk cap แต่พอเปิด datasheet แล้วพบว่าไม่ต้อง และวัดยืนยันแล้ว"**
> เป็นเนื้อหารายงานที่ดีกว่าการใส่ตัวเก็บประจุไปเฉยๆ มาก

### LED1 เขียวอมเหลือง — แก้ด้วยเฟิร์มแวร์ ฟรี

LED1 ถูกประกอบเป็น `KT-0805YG` แล้ว สีใกล้ LED2 (เหลือง) เกินไป
ถอดเปลี่ยนเสี่ยงทำแพดหลุด → **แยกด้วยจังหวะกะพริบแทนสี**

```
NORMAL  →  ติดค้าง
WATCH   →  กะพริบ 1 ครั้ง/วินาที
ALARM   →  กะพริบ 5 ครั้ง/วินาที + buzzer
```

> 🔑 จังหวะแยกออกจากกันชัดกว่าสีเสมอ โดยเฉพาะกับ**คนตาบอดสี** ซึ่งควรคิดอยู่แล้ว
> ในอุปกรณ์ที่ทำเพื่อผู้ป่วย → **เขียนในรายงานว่าเป็นการออกแบบเพื่อการเข้าถึง**
