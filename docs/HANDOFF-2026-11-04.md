## 2. build / flash

1. ใช้ **ESP-IDF v5.5.6** (เปิด ESP-IDF PowerShell / terminal ที่โหลด IDF แล้ว)
2. **ลบ `firmware/sdkconfig` ก่อน build ครั้งแรก** — ไม่งั้นค่าใหม่ใน `sdkconfig.defaults` (partition 4 MB · tcpip core 0) จะไม่ถูกใช้
3. สร้าง `firmware/main/secrets.h` จาก `firmware/main/secrets.h.example` ใส่ชื่อ/รหัส hotspot มือถือที่จะใช้วัน demo
   🔴 **ห้าม commit ไฟล์นี้** (ถูก ignore ด้วย `.gitignore: secrets.*` อยู่แล้ว · repo เป็น public)
   ไม่มี `secrets.h` ก็ build ได้ แต่จะไม่มี SNTP → ไม่มีเวลาจริง → ไม่เขียน CSV
4. ```bash
   cd firmware
   idf.py set-target esp32s3
   idf.py build
   idf.py -p <PORT> flash monitor
   ```
   หลัง build ควรเห็น `CONFIG_LWIP_TCPIP_TASK_AFFINITY_CPU0 1` ใน `firmware/build/config/sdkconfig.h`
5. **ทางสำรองถ้า dashboard มีปัญหา** (build แยกโฟลเดอร์ ไม่มี Wi-Fi dashboard):
   ```bash
   idf.py -B build/web_off -DWEB_ENABLE=0 build
   ```

## 4. ข้อจำกัดที่ต้องรู้ตอน demo (ข้อเท็จจริง)

- **โมเดลเทรนจากข้อมูลนอกกล่อง** (25–30 ต.ค.) → ใช้กับเครื่องตอนอยู่ในกล่องไม่ valid ถ้าไม่เก็บข้อมูล/เทรนใหม่ในกล่อง (ข้อตัดสิน 23 ต.ค. ใน `CLAUDE.md` §10)
- **CO ALARM ทดสอบด้วย host test เท่านั้น** — ยังไม่เคยทดสอบด้วยเฟรมจำลองบนบอร์ดหรือกับ CO จริง (ถ้าทำ B4 ได้ ให้แก้ข้อนี้ตามผล)
- **`co_ppm` ไม่ได้สอบเทียบ** — ใช้แสดง/บันทึกเท่านั้น
- **CO FAULT บังไฟของ ML ทั้งหมด** — ถ้าไม่ต่อ ZE07 (หรือ ZE07 เงียบเกิน 6 s) เครื่องจะขึ้น FAULT และสถานะจาก ML จะไม่แสดงบนไฟ
- **dashboard เปิดไม่เกิน 2 เครื่อง** — `WEB_MAX_SOCKETS = 4` (`firmware/main/task_config.h`) และยังไม่เคยวัดกับหลาย client บนบอร์ด (B3)
- **ข้อความ `CLAUDE.md` §8 ต้องอยู่บนตัวกล่อง** (และในสไลด์)
